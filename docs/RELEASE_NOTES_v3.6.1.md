## v3.6.1（2026-10-16）

> **「自动续期」不再是一句没有期限的承诺。**

这是一次 **patch** 升级，只改一处：卡片现在会告诉你**刷新令牌**何时到期 ——
在那之前访问令牌会自动续期，在那之后自动续期就彻底停了。

---

### 修复

- **刷新令牌的到期时间对用户完全不可见**

  **问题**：卡片一直只写一句话 ——

  ```
  访问令牌 2026/10/25 04:08 过期（自动续期）
  ```

  这句话是**对的**，而且**一直对** —— 直到**刷新令牌**到期的那个瞬间，
  自动续期就**永久停止**了。一个读了几个月「自动续期」的用户，
  没有任何理由预期这件事，而卡片上也不会出现任何征兆。

  **根因**：刷新令牌的到期时间**被解析了、也被存下来了，但从来没送到浏览器** ——
  状态接口里根本没有这个字段，所以卡片无从显示。这不是文案问题，是数据没通。

  **现在**：状态接口暴露刷新令牌到期时间，卡片**按账号**在临近到期时提示：

  | 情况 | 卡片显示 |
  | --- | --- |
  | 剩余 **30 天**以内 | 提醒（警告色），写明**到期时间**与**还剩几天** |
  | **已到期** | 明确说明「自动续期已停止」，并给出恢复方式（重新登录一次 Trae） |
  | 还很远 | **不显示** |
  | 凭据本身不带该字段（如 CLI 令牌） | **不显示** —— 不伪造一个期限 |

  最后两条是刻意的：健康的令牌不该在每一个账号行都占一行文字（否则用户会学会忽略它），
  而**编造**一个到期时间比不显示更糟 —— 用户会照着它安排自己的操作。

  > 这条不是推演出来的理论问题：我们在排查 `#38` 时**亲身遇到过** ——
  > 某个区域插件自存的凭据访问令牌已过期、刷新也返回 401，
  > 而卡片上一直写着「自动续期」。当时只能靠人肉发现。

---

### 测试

- 新增 **5** 例，覆盖三种状态与两个边界：健康不显示、临近显示截止日与剩余天数、
  已过期显示错误态、无该字段不伪造、**最后一天仍算「未过期」**（差一天的判断错了，
  会让用户以为续期已经停了，而其实还在工作）。
- **变异验证**：去掉 30 天提醒窗口 → 2 例变红；在缺少字段时伪造一个期限 → 1 例变红。
- 全仓 **660** 例测试通过，类型检查通过。
