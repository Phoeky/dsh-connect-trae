## v3.4.3（2026-10-13）

> **保存模型列表时，终于有「正在进行」的反馈了。**

这是一次 **patch** 升级。保存状态此前只是**控件变灰 + 按钮文案从「保存」变「保存中…」**——
用户盯着某个具体行等它落地时，屏幕上没有任何「正在进行」的迹象。这次补上一层忙碌遮罩，
并把它原先自造的几处配色与动效换成宿主自己的令牌与节奏（同族 `dsh-connect-workbuddy`
4.4.2 修的是同一处，本版保持一致）。

---

### 新增

- **保存 / 写设置时有一层忙碌遮罩。**

  遮罩覆盖卡片的**两条**写路径：`saveModels`（保存模型列表）与 `writePreference`
  （「跟随 Trae 当前登录的账号」与「在输入框显示积分」两个开关）。
  遮罩在该写路径的 `finally` 里随忙碌标记一起落下 —— 也就是 **Host 重读落地的时刻**，
  所以延迟从「看不见」变成「看着它发生」。

  遮罩是**半透明**的、下方的列表仍然可见：用户正在看某一行变化，把它藏起来反而帮倒忙。

---

### 修复

- **遮罩的配色改用宿主自己的令牌**（改前若照抄旧写法，四处自造值全部出问题）：

  | | 改前 | 改后 |
  |---|---|---|
  | 卡片底色 | `--dsw-alias-bg-primary`（**宿主根本没这个变量**） | `--dsw-alias-bg-layer-2` |
  | 遮罩底色 | 写死 `rgba(0,0,0,.38)` | `--dsw-alias-bg-mask-1` + `--dsw-mask-blur` |
  | 阴影 | 手写的 `0 8px 28px rgba(0,0,0,.35)` | `--dsw-elevation-prominent` |
  | 提示文字 | `label-tertiary`（宿主最暗的一档） | `label-secondary` |

  第一条是**这一版的根因**：`--dsw-alias-bg-primary` 在宿主的令牌集里**不存在**
  （宿主只有 `bg-base` / `bg-layer-1..3` / `bg-module-platform` / `bg-overlay` 等），
  于是每一次都回退到写死的近黑 —— 遮罩卡片就是一块黑板子，上面的字看不清。
  第二条那层写死的半透明黑既不跟随主题、也没有宿主的模糊，在浅色主题下尤其不对劲。
  第四条则是把**给元数据用的最暗一档**拿来承载一句要等的人必须读的话。

- **spinner 换成宿主同款弧线。**

  此前是 18px 的 CSS border 环、`.7s` 匀速转 —— 比宿主自己的状态转圈
  （`_dsh-state-dot-spin`：SVG 弧线 + dash 呼吸、`1.5s`）**快了近一倍**。
  比起形状本身，**这个速度差才是它看着廉价的主因**。

  现按宿主 bundle 里实测到的几何逐条对齐：弧线 `stroke-dasharray 12 150` + dash 呼吸、
  `1.5s` 节奏、`currentColor` 继承所在层级；`prefers-reduced-motion` 下**降级为静态弧线**
  （与宿主降级方式一致），而不是把动画整个关掉；另补 `aria-hidden`，
  免得在 `role="status"` 之外再多报一次。

### 测试

- **+4**（`tests/card-styles.spec.tsx` 5 → 9，全仓 **594 → 598**）：

  - 遮罩选择器守卫（要求整条 `{` 结尾匹配，避免改名前缀后被子串误判为存在）；
  - 弧线节奏守卫（钉住 dash 关键帧与 reduced-motion 降级，防止退回自绘 border 环）；
  - 令牌白名单补三条 —— 白名单断言「大小必须等于实际用到的令牌数」，
    所以引入新令牌后必须同步补齐，否则整套报错；
  - **渲染守卫** —— jsdom 不做层叠，前几条都只证明样式表里有这些名字。
    这条在写盘挂起的条件下点「跟随 Trae 当前登录的账号」，断言遮罩**确实进 DOM**
    （`role=status` / `aria-busy=true` / `aria-live=polite`）、文案正确、弧线与卡片都在，
    写盘落地后卸载。

  变异验证：把 `.dsm-trae-veil{` 改成 `.dsm-trae-veilz{` → **仅**选择器守卫变红；
  把 `visible={saving || savingSettings}` 改成 `visible={false}` → **仅**渲染守卫变红。

  **一处如实记录**：同族那条「模板字符串被反引号截断」的守卫在本仓库**不会比现有工具更早报警** ——
  这里的 `vite/oxc` 与 `tsdown` 都会直接报解析错误。真正拦不住截断的是 `tsc`
  （实测被截断的文件 `tsc` 仍 `exit 0`），而这正是同族当初能静默中招的原因。
  那条守卫作为兜底保留，没有把它说成一道拦得住的防线。

### 升级

```bash
dsh plugin install dsh-connect-trae@3.4.3
```

升级后重启 DSH 即可。这次改的是设置卡片**保存时**的观感与动效，不涉及任何请求路径、
凭据读取或额度消耗 —— 除每日签到外，插件的查询仍然全是只读的。
