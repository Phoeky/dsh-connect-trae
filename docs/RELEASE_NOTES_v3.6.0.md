## v3.6.0（2026-10-16）

> **多个账号可以并存了。**

这是一次 **minor** 升级，新增两件事：**账号导入 / 导出**（issue #37），
以及一条针对 **上游未下发 function 配置** 的诊断改进（issue #39）。

---

### 新增：账号导入 / 导出（#37）

在此之前，想在这台机器上用第二个 Trae 账号，只能把凭据**手工写进默认路径**、顶掉上一个 ——
繁琐，而且一旦忘记原账号就找不回来了。现在卡片账号区多了一行 **「导入 / 导出账号」**：

| 操作 | 步骤 |
| --- | --- |
| **导出** | 勾选若干账号 → 下载一份 JSON（`trae-accounts-YYYY-MM-DD.json`） |
| **导入** | 选择文件 → 看**脱敏预览** → 勾选 → 导入 |

- **脱敏预览**只显示账号标识与「是否有 Token」，**不显示凭据本身**。
- 文件格式与同族 **`dsh-connect-workbuddy` 互通**，两边导出的文件可以互相导入。
- 导入按账号去重：同一账号再次导入即**覆盖更新**。
- **导入按钮在未登录时也可用** —— 一台从没登录过的机器，正是最需要导入别处导出的文件的时候。

> ⚠️ **导出的文件里是有效 Token，请当作密码保管。**

**顺带把存储升级成了多账号。** 本插件原先每个区域只保存**一个**凭据，导入的第二个账号无处可放；
现改为**每区域一个文件保存凭据数组**（格式版本 1→2）。**旧文件仍可正常读取**，并在下一次写入时自动升级，
不需要你做任何迁移。

#### 区域门禁是「正向匹配」

导入文件里的 `domain` 是**文件作者可控**的值，而插件「认不出就当作国内版」的规则对**上游下发**的数据是对的、
对**导入文件**是危险的：一个伪造或拼错的域名会被塞进国内版。因此导入走一条**只认正向识别**的通道 ——
空值、认不出的值、以及明确属于另一区域的值一律**跳过并计数**，绝不静默落库。
国内版与国际版是两条**并行计费**的通道，跨区导入会导致跨区计费，这里不做任何猜测。

### 修复

- **修复一个会丢账号的写入缺陷**（在实现导入功能时发现）：
  刷新路径原先把「刚刷新好的那一个凭据」当作**整个文件**写回。在单凭据时代这没有问题；
  一旦一个区域能保存多个账号（正是导入带来的），**刷新一个账号就会把同区域的其他账号全部删掉**。
  已改为**读-改-写**：只替换被刷新账号自己那一条，其余条目原样保留。回归测试专门钉住了这一点。

- **上游未下发 function 配置时，报错读起来不再像本地故障（#39）**：
  - 报告者遇到的现象是每次调用都返回 `2001 no function config found for appId=…`。他据此排查了一圈
    本地凭据与插件版本，最后才发现问题在**服务端** —— 上游的 `get_detail_param` 当时对**每个** SOLO
    function 都返回空的 `config_info_list`，随后**自行恢复**。
  - 现在：① **`2001` 有了明确文案** ——「上游尚未下发本通道的 function 配置（这是上游侧的状态，
    不是本地凭据或配置问题）」；② 当**所有** function 都返回 200 却一条配置都没有时，目录读取会抛出专用的
    `TraeEmptySoloDirectory`，把「上游没下发」与「所有 function 都请求失败」区分开。
  - 两条都**不暗示需要重新登录**，因为这个条件是**会自行恢复**的。

### 测试

- 新增 **34** 例，覆盖导入导出格式、导入路由、存储升级、以及端到端的「一处导出 → 另一处导入」。
