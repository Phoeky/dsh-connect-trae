## v3.8.0（2026-10-18）

> **国内区多了一个面板：企业版。**

这是一次 **minor** 升级，也是本插件第一次**改变计费方**的版本。

同一张 CN 凭据，如果它属于 `tob_online` 租户，会被**两个网关同时服务**：消费池扣个人积分，
租户池扣企业额度。同一模型、两种付费方——所以「谁付钱」必须由你选，不能由插件猜。
这就是第三个面板存在的原因。

顺带修掉两个只在企业网关上才现形的故障，以及一个**会让卡片和账单对不上**的 bug。

---

### 新增：企业版面板

供应商开关从「按区域」改为「按面板」。三个面板并列，各有**独立开关、独立账号绑定、
独立模型选择**：

| 面板 | provider | 默认开关 |
| --- | --- | --- |
| 国内版 | `trae` | 开 |
| **企业版** | `trae-enterprise` | **关** |
| 国际版 | `trae-global` | 开 |

**企业版默认关闭**，因为纯个人账号用不了企业池——默认放开等于给所有人塞一条一用就失败的
provider。**升级本版不会改变你现有的任何行为**：原来两个面板的用户什么都不用做。

`cn` 区现在并列发布两个 provider，计费池完全不同：

| provider | 计费池 | 说明 |
| --- | --- | --- |
| `trae` | 消费 SOLO | 行为与此前完全一致，**永不碰**企业网关 |
| `trae-enterprise` | 企业租户 | **不回落**，失败如实报错 |

路由在**构建 provider 的客户端时固定**，不存在「按调用猜一次」。shim 为每个 provider 提供
一条 bearer 路由并按 bearer 分派，未知 token 直接 401，不会悄悄退回第一条路由。

### 修复

**计费账号与卡片显示可能不是同一个（本版最重要的一个）**

`accounts()` 从**已经为展示过滤过**的列表推导「哪一行是高亮的」，而 `current()` 从**全量**
登录里解析真正计费的凭据。两者是不同的数据源。

后果：开着 `hideTenantAccounts` 且企业号排序在前时，卡片高亮个人号、聊天扣企业池。更糟的是
卡片里的 `rescanAccounts` 会把这个**错误的绑定存下来**，让分歧固定下来。

现在 `inUse` 拆成两个入参，让两条路径的语义各自正确：

- **显式绑定**走全量登录——展示过滤不该缩小「用户选的号」的查找范围。
- **没有绑定时**的默认值走过滤后列表——隐藏企业号是**计费决定**，不是展示细节。

`current()` 与 `accounts()` 传同一对参数，结构上不可能再分歧；正在计费的账号也永不会被
从列表里隐藏。

**`deepseek-v4.1-flash` 等模型报 `4001`（`param is invalid`）**

网关的 `config_name` **区分大小写**，而 Remote 目录给的是小写、网关只认 `DeepSeek-V4.1-Flash`。
三处一起修：

1. `modelConfig` 补上 `wireConfigName`。DSH 设置通道用它重建文档，**未声明的字段会在每次保存时
   被丢掉**——映射一丢，该模型就要等到下一次发现才能用。
2. `fetchModels` 改为从**客户端所钉的那条网关**读名录。两个池的名录不同
   （`DeepSeek-V4.1-Flash` 只有企业池列），原本钉在企业池的客户端去读消费池名录，
   永远发现不了自己池的独占模型。
3. `TraeSoloBridge` 查表改为大小写不敏感，映射都落空时退回目录行自己的 id。

**企业网关的拒绝形态是 HTTP 200**

它返回 200，但首帧是 `event:error`（`code 4001`）。原先这会被当成「正常结束但没有任何内容」，
表现成「这一轮助手什么都没说」。现在会被转成真正的客户端错误；正常流则逐字节重放给调用方。

**企业网关要求每次调用带 `session_id`**，而消费网关会拒绝带它的请求体，所以只在该路由上加。

### 测试

- 企业版相关新增 **38** 项：按 bearer 分派、`session_id` 只在该路由、200/`event:error` 识别、
  流原样透传、名录按路由读取、大小写映射与 schema 往返、租户账号作用域、4222 可读等。
- **计费一致性新增 2 例**：`accounts()` 里 `selected` 的那一行必须就是 `current()` 计费的那个
  账号；被隐藏的账号正在计费时仍须留在列表里。**两例在修复前均变红**
  （`expected 'tenant-user' to be 'personal-user'`）。
- 用真实 `tob_online` 帐号实测：企业路由返回 PONG、带 `session_id`、个人 `consumed_amount` 不变。
- 全仓 **710** 例通过（原 670 + 40），双 tsconfig 类型检查通过，构建通过。

### 从旧版本升级

直接升级即可，**无需任何配置改动**。企业版面板默认关闭，所以升级后你的模型列表
**一个条目都不会多**。

如果你**确实**有企业租户账号：打开卡片里的「企业版」tab，把它打开，然后在该面板里绑定账号。
两个面板可以绑同一张凭据、也可以绑不同凭据，模型选择互不覆盖。

> ⚠️ 企业版**不回落**。它失败就是失败，不会退到消费池——否则你会以为在用企业额度，
> 实际扣的是个人积分。这正是本版要消灭的那类歧义。
