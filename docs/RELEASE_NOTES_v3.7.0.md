## v3.7.0（2026-10-17）

> **对齐 DSH 0.2.1-rc.1 —— 并证明「没坏」这件事。**

这是一次 **minor** 升级。宿主把 `@earendil-works/pi-ai` 从 `^0.85.1` 抬到了 `^1.1.0`，
这是 0.2 线里**唯一有行为影响**的变更。

结论先说：**你的 Trae 模型没有因此出问题**。但这不是运气 ——
是 3.4.2 就埋下的双向适配兜住了它。本版把这条结论**从「推理」变成了「被测住的对照」**，
并修掉升级后才暴露的类型契约。

---

### 背景：宿主那一侧确实有一处静默故障

DSH 0.2.1-rc.1 的 `dsh-llm-pi-ai` 依赖 `pi-ai@^1.1.0`，但它**自己仍然产出旧版上下文信封**
（`{ systemPrompt, tools, messages }`）。而 pi-ai 1.1.0 **只**认新的 transcript 形状，
顶层那两个字段它**一次都不读**。

于是任何「把宿主信封原样透传」的插件，在 0.2.1-rc.1 上都会**静默**丢掉：

- 整个 **system prompt**（→ 模型不再知道自己是 DeepSeek Harness 的 agent）
- **全部工具声明**（→ 模型永远无法调用 `pwsh` 等工具）

**不报错、不崩溃、usage 正常** —— 只是每一轮都变成了「没有工具、没有系统提示」的裸对话。
这类故障在日志里一个字节都不会留。

### 我们的实测对照

真实 `createProvider` + 真实 `openAICompletionsApi()` + 本地 SSE 服务器，捕获**线上请求体**：

| 场景 | 线上 `roles` | 线上 system | 线上 `tools` |
| --- | --- | --- | --- |
| **本插件**（走适配器） | `["system","user"]` | 完好 | **1** ✅ |
| **不**走适配器（假设直通） | `["user"]` | `null` | **0** ❌ |

第二行就是上面说的静默故障。本插件在第一行。

### 修复

- **pi-ai 1.1.0 的类型契约断裂（升级后才暴露）**

  **问题**：`npx tsc` 报 10 处 `TS2345`。

  **根因**：1.1.0 把 `ProviderStreams` 的第二个参数改成了带 `unique symbol` 品牌标记的
  `TranscriptContext` —— 这个类型**只有** `normalizeContext()` 能产出，是一道有意的类型护栏。
  而本插件的适配层恰恰要处理**两代**上下文，其中旧代形状**必须**是无品牌的。

  **修法**：在这**唯一一条边界**上做一次显式转型，并把「为什么品牌在这里不可诚实获得」
  写进代码注释 —— 而不是在十几处调用点散落 `as never`。

  > 这个冲突在 0.85.1 下**根本不存在**，是升级 pin 到 1.1.0 之后才现形的。

---

### 变更

- **开发树对齐宿主实际随包版本**，让本地 typecheck 与测试跑在与用户**字节一致**的契约上：
  - 13 个 `@deepseek-ai/dsh-*` → `0.2.1-rc.1`
  - `@deepseek-ai/cordis` → `^4.0.5`
  - `@deepseek-ai/schemastery` → `3.18.5`（`dsh-llm-pi-ai@0.2.1-rc.1` 声明 `~3.18.5`）
  - `@earendil-works/pi-ai` → **`1.1.0`（精确固定）**

  > 为什么不用 `^1.1.0`：那样会解析到 `1.3.0`，本地测试就**不是**用户实际运行的那份契约了 ——
  > 上面那个类型断裂也就不会在本机复现。

- **`@earendil-works/pi-ai` peer 上界收窄为 `<2.0.0`**：原先是 `>=0.85.1` 且**没有上界**，
  会把未审阅的 2.x 一并放行。

---

### 测试

- 新增 **线上请求体矩阵**：起真实 SSE 端点，断言线上 body 里 `roles[0] === 'system'`、
  system 文本等于原提示、`tools` 长度为 1；并覆盖「已归一化输入不会被二次包裹」的幂等性。
- 新增 **反向对照**：**不**套适配器时，现代副本会把提示与工具全部丢光 ——
  这条钉住「适配器为什么是承重的」。只测正向的话，将来有人删掉适配器，测试仍可能因为别的原因绿着。
- **变异验证**：把 modern 分支改成直通 → 线上请求体用例立刻变红。
- 全仓 **663** 例测试通过（原 660 + 3），双 tsconfig 类型检查通过，构建通过。

---

### 已核对、无需改动

- **peer 范围**：`0.2.1-rc.1` 对现声明**已判通过**。DSH 用
  `satisfies(runtime, range, { includePrerelease: true })` 求值，且只校验 `@deepseek-ai/dsh*` ——
  semver 的「预发布悬崖」只在**默认选项**下成立，在这里不触发。
- **宿主 API**：`dsh-llm` / `dsh-settings` / `dsh-host-webserver` / `dsh-llm-pi-ai` 消费点签名未变。
- **客户端外壳**：产物仍只 `require` react / react-dom / react/jsx-runtime，槽位与主题令牌未变。

---

### 从旧版本升级

直接升级即可，**无需任何配置改动**。本版不改变任何用户可见行为 ——
它保证的是「在 0.2.1-rc.1 上，行为**和以前一样**」。

> 如果你在使用 0.2.1-rc.1 且**没有**升级到 3.7.0：你的 system prompt 与工具声明**仍然是完整的**
> （3.4.2 起的适配一直在保护你）。本版补的是类型正确性与回归防线。
