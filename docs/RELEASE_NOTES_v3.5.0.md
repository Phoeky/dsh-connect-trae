## v3.5.0（2026-10-14）

> **积分读数不再只有一个固定位置 —— 位置交给你选。**

这是一次 **minor** 升级（新增一个可选设置）。它学自同族 `dsh-connect-workbuddy` 的 issue #62：
把「读数显示在哪里」做成一个选项，**默认值与升级前完全一致**，所以你什么都不做的话，
屏幕上的东西一个像素都不会变。

---

### 新增

- **输入框读数的显示位置可选：输入框工具栏 / 输入框下方。**

  | 选项 | 位置 | 说明 |
  | --- | --- | --- |
  | `输入框工具栏`（**默认**） | `conversation.input.left` | 「专家」与模型选择器之间，即现在的样子 |
  | `输入框下方` | `conversation.composer.dock` | 「轮次 / 步数 · tok/s · token · 缓存命中」那一行 |

  选「输入框下方」时，读数是**追加**在官方那几颗统计**之后**（`order: 10`，外壳自己的统计注册在 0），
  所以官方统计仍在最左，不会被动替换掉。

  **位置按区域分别设置** —— 国内版与国际版各存各的（`regions.<region>.creditPosition`），
  你可以只把国内版的读数挪走。控件在卡片「设置」区，紧挨「在输入框工具栏显示积分读数」那个勾选框。

  **为什么要给第二个位置**：输入框工具栏是一个**共享的 list 插槽** —— 外壳自己的控件和**任何其他插件**
  都注册在那里，而共享插槽**无法保证每个占用者都可见**。同族的报告者装了第三方插件
  （`dsh-auto-continue`）之后，积分读数就**整个消失了**。本插件其实已经因为这个原因丢过一次这行读数：
  它早年放在**侧边栏底部**（一个共享的根级行），与同族的两行并排时被挤成只剩一个「Tr」的残片，
  2.12.0 才迁到输入框工具栏。**同一个坑踩了两次，这次把位置交给你。**

### 修复

- **区域被关闭后，它的积分读数仍在输入框工具栏里渲染。**

  把某个区域的供应商关掉时，Host 会把该区域的 adapter 路由与可配置供应商条目**一并撤下**，
  模型选择器里也不再有它 —— 但读数仍然画在那里，并且它的取数请求**注定失败**。
  根因是 gate 只检查了「显示积分」那个开关，**从未检查区域开关**。

  现按 Host 的同一套 opt-out 规则（只有显式 `false` 才算关闭）在 gate 里补上这一判，
  用的是卡片上那个区域开关**同一个 reader**，所以卡片和 gate 不可能对「这个区域开没开」产生分歧。

  这条不是学来的，是**本次移植时被新守卫逼出来的**：同族的 gate 一直有这一判，是本插件漏了。

### 设计取舍（两条，都记在 CHANGELOG 里，免得后人改回去）

- **两个席位都无条件注册，决定权在 gate 里一处**（席位不符就 `return null`）。
  若改成「按设置只注册当前席位」，每次改设置都要**重新注册插槽** —— 而本仓库的文件头已经写明
  这种绑定是脆的（rc.6→rc.7 的 `id`/`order` → `key`/`priority` 改名就是同类问题），
  而用户是「一边看着结果一边改」的。现在改设置只是一次 settings 写入。
- **卡片控件读的是设置文档，不是 Host 的 usage 应答**（这里**故意与同族不同**）。
  同族那样做是因为它的 0.1.7 部署上浏览器设置镜像**实测过期**；本仓库没有复现到这种过期，
  而读镜像才能让控件**首帧就是对的** —— 只靠 usage 文档喂值的控件会先停在默认值上等一次网络往返，
  这正是「看起来没生效」的观感。这一点有守卫钉住。

### 测试

- **+19**（全仓 **598 → 617**，测试文件 57 → 58）：

  - `tests/credit-position.spec.tsx`（新增 13 例）：默认 `composer`（含设置存在之前的 profile、
    手改的未知值 `'sidebar'`）；**按区域**而非全局读取；整段设置与裸 `regions` 映射两种入参都接受
    （传错形状在本卡片上真的出过货）；写入只改该区域该字段（模型列表 / 预算 / enabled / 兄弟区域都不动）；
    席位与两个开关相互独立；gate 在**指定席位渲染 / 另一席位渲染 0 个 / 两个席位都不渲染（隐藏或区域关闭）/
    别的 provider 两个席位都不渲染 / 按会话所指区域取席位（CN 与 AI 各在各自席位）**；
    以及 Host 侧 `creditPosition()` 与浏览器侧 `regionCreditPositionOf()` **两边答案一致**（含 schema 默认值）。
  - `tests/card-composer-credits-switch.spec.tsx`（新增 6 例）：控件默认值、**跟随标签页切换**、
    写入是**整槽合并**（不丢模型选择、不动另一个区域）、区域关闭时**禁用而不是隐藏**、
    与显示开关相互独立（隐藏后仍保留所选席位）、只读 scope 拒绝写入。
  - `tests/client-activation.spec.tsx`（更新 2 处 + 新增 1 条断言）：插槽清单由 3 个变 4 个，
    并**钉住两个席位的 slot id 互不相同** —— 两个注册共用一个 id 会让后一个静默替换前一个，
    于是设置能选到一个已不在册的席位、读数反而彻底消失（正是本特性要修的那个缺陷）。
    测试替身原先只认 `key` 字段，现在同时认 `id`/`key`（真实的 0.1.7 注册表两者都用），
    否则一条关于 slot 身份的新断言会静默读到 `undefined` 而假绿。

  **变异验证**（各自变红后恢复）：删掉 gate 的席位判定 → 4 例红；把读取的默认值去掉
  （升级前的 profile 读成 `undefined`）→ 4 例红；只注册一个席位 → 2 例红；
  控件不读所存席位 → 2 例红。构建产物核对：`lib/client.js` 内两个插槽名与两个 slot id 均在。

### 升级

```bash
dsh plugin install dsh-connect-trae@3.5.0
```

升级后重启 DSH 即可。**升级不会移动任何人的读数**：默认仍是「输入框工具栏」，即现在的位置；
`showPointsInMainUi` 的语义、默认值与写入路径一律未改动。本次只涉及一个设置项与一处渲染判定，
不涉及任何请求路径、凭据读取或额度消耗 —— 除每日签到外，插件的查询仍然全是只读的。
